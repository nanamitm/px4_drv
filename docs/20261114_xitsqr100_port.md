# PIXELA XIT-SQR100 対応の移植と J.83 Annex B の追加

この文書は、[yyya-nico 氏のフォーク](https://github.com/yyya-nico/px4_drv/tree/feat/support-sqr100) の PIXELA XIT-SQR100 対応をこのリポジトリへ移植し、スカパー！プレミアムサービス光 (J.83 Annex B、5.6Msps) の選局を加えた記録です。

この記録の作成時点で XIT-SQR100 の実機はなく、確認できたのはビルドと模擬 I2C の自動試験までです。  
以下で「検証環境」は、Windows 11 Pro (x64)、Visual Studio 2022 (v143) の開発環境と、同じ PC の WSL (Ubuntu 24.04) を指します。

## 移植元と移植元の確認範囲

移植元は `feat/support-sqr100` の `9322a5d` (2026年10月) です。  
移植元の記録では、Linux と Windows の実機で地デジ・BS・CS の選局と受信、内蔵カードの ATR と APDU を短時間確認しています。  
同じ記録で、Linux 版の地デジの受信開始直後の TEI と形式不正、数時間以上の連続受信、USB の抜き差し、基板電源の GPIO の信号名と極性は未解決または未確認とされています。

## 構成

| 部品 | 役割 | 接続 |
|---|---|---|
| IT9303 (IT930x) | USB ブリッジ・TS 入力・GPIO・B-CAS の UART | USB `06B8:106B` |
| CXD2856ER | 復調器 | I2C バス 3、SLV-T `0x64`、SLV-X `0x66`、水晶 24MHz |
| CXD6866AER (Sony FREIA) | 地上波・ケーブル・衛星共用のチューナー | 復調器の I2C リピーター経由で `0x60` |

受信機は1台で、BS/CS アンテナへの給電には対応していません。  
TS は受信機番号のない通常の TS (同期バイト `0x47`) で、`driver/ts_sync.h` の `px4_ts_has_plain_sync()` で同期を判定します。

## このリポジトリへ合わせた変更

### 内蔵カードリーダー

XIT-SQR100 のカード検出は GPIO H15 (挿入中 High)、リセットは GPIO H1 で、通常機種の GPIO H6 (Low Active) と GPIO H14 と異なります。  
Windows ドライバーの拡張 B-CAS API と同じ配線のため、`struct it930x_bridge` の `bcas_is_extend` で切り替える形を移植元から引き継ぎました。  
ゼロ初期化の値 (false) が従来の配線になるため、Linux 版の `kzalloc` と WinUSB 版の `memset` で初期化している既存機種の動作は変わりません。

Linux 版のカード層 (`driver/px4_card.c`) は、移植元と異なり機種共通の `/dev/px4card/<ID>` を使うため、XIT-SQR100 は `set_power` コールバックで基板電源を参照します。  
移植元の実機の確認で、カードの ATR を受信するには GPIO H7 を Low にする必要があったため、カードの電源投入のたびに GPIO H7 を Low にします。  
カード検出の入力設定は GPIO H6 の固定から、配線に応じた `it930x_bcas_detect_gpio()` へ変えました。

`px4_card_guids` は PID だけで INF の DeviceInterfaceGUIDs を引いていましたが、XIT-SQR100 は他社の VID のため、VID と PID の組で引く形へ変えました。  
`pcsc/tests/check_card_guids.py` も VID と PID の組で照合し、VID `0x06b8` のうち XIT-SQR100 だけを照合の対象に加えました (PIX-DT295 は Linux 版の対象外)。

### 基板電源と TS

基板電源は GPIO H5 を High にして 50ms、GPIO H2 を Low にして 100ms、High にして 20ms 待つ、移植元の手順をそのまま使います。  
GPIO H5 と H2 の信号名は確かめられていないため、待機時間を含めて値を変えていません。  
チューナーとカードは、PX-MLT 系と同じく、どちらかが使っている間は電源を切らない参照の契約で電源を共有します。WinUSB 版は `BackendPowerState` を使います。

IT930x の USB 転送用の TS の暗号化は、移植元の Linux 版と同じく `0xdab0 = 1`、`0xdaae = 0` で無効にします。  
移植元の WinUSB 版にはこの書き込みがありませんでしたが、IT9300_setTsEncrypt(false) と同じ公開の手順で、有効のままだと TS の一部が化けるため、WinUSB 版にも加えました。WinUSB 版でのこの差の影響は実機で確認していません。

### TS クロック

XIT-SQR100 の TS はシリアルの連続クロックで、`struct cxd2856er_config` の `serial_ts_clock` で選びます。  
地デジ (高い周波数・ハーフレート) と BS/CS (中間の周波数・フルレート) の値は、移植元が Windows の USB キャプチャと照合した値です。  
`serial_ts_clock` が false の PX-MLT 系の値は変えていません。WinUSB 版の PX-MLT 系の受信機はメンバーがゼロ初期化されないため、false を明示しました。

### C/N の換算表

C/N の生値の換算表は、Linux 版は `driver/pxmlt_device.c` から `driver/cxd2856er_cnr.c` へ、WinUSB 版の ISDB-S の表は `pxmlt_device.cpp` から `cxd2856er_cn_table.hpp` へ移し、PX-MLT 系と XIT-SQR100 で共有しました。  
移す前と後の探索を、生値の全範囲 (0〜65535) で比べ、Linux 版の地デジ・BS/CS・ISDB-C の 196608 通りと WinUSB 版の ISDB-S の 65536 通りがすべて一致しました。

### 移植しなかったもの

移植元の検証記録 (`docs/2026*_xitsqr100_*.md`) は、このリポジトリのコードと異なる版の記録のため、取り込まずにこの文書から参照しています。  
移植元の udev ルールにある VID `06b8` の USB 電源管理の指定は、XIT-SQR100 で必要とする根拠が記録にないため、追加を見送りました。  
macOS 版の DriverHost への追加は、macOS での確認手段がないため対象外です。

## J.83 Annex B の追加

### 復調器

復調器の J.83B の手順 (起動・停止・選局し直し・ロック判定・C/N) は、PX-MLT 系のために実装済みの `cxd2856er_wakeup_j83b()` などをそのまま使います。  
J.83B 5.6Msps の IF (3.75MHz) は、Sony のコード (TBS の `cxd2878.c` の `iffreqConfig.configJ83B_5_60`) でチューナーの種類によらない値です。

### チューナー

Sony の FREIA の地上波の設定表 `g_terr_param_table_freia` には、日本の J.83B 5.6Msps 専用の行 `SONY_FREIA_DTV_SKP_OPT` があり、Sony の `freia_tune()` は `SONY_DTV_BW_J83B_5_60_MSPS` にこの行を使います。  
出典は TBS の `cxd2878.c` ([koreapyj/cxd28xx `c5fa27e`](https://github.com/koreapyj/cxd28xx/blob/c5fa27eecbe80633cbb365cc44656daea1c0e2e3/cxd2878.c)、GPL-2.0-only) で、PX-MLT 系の J.83B の復調器の手順と同じ資料です。

| 項目 | ISDB-T 6MHz | J.83B 5.6Msps (`SKP_OPT`) |
|---|---|---|
| IF_BPF_GC (0x69 の下位4ビット) | 0x06 | 0x03 |
| RFOVLD_DET_LV1 (0x6B) | 0x0E | 0x0B |
| IFOVLD_DET_LV (0x6C) | 0x03 | 0x03 |
| FIF_OFFSET (0x6E) | -9 (0x17) | -5 (0x1B) |
| BW_OFFSET (0x6F) | -5 (0x1B) | +2 (0x02) |
| OVLD (0x3C〜0x3E、0x52、0x8B) | FC 9C 8F、00、75 | FC 87 CF、78、05 |

OVLD のレジスターは、Sony の `freia_tune()` でケーブルの方式 (`CABLE_6`・`CABLE_8`・`SKP_OPT`) だけが別の値になります。  
FIF_OFFSET と BW_OFFSET は、PX-MLT 系のチューナー (CXD2858ER) の J.83B 5.6Msps の行と同じ値です。  
選局の手順 (TER_tune、50ms の待機、TER_tune_end) と停止 (TER_fin) は ISDB-T と共通で、移植元の ISDB-T の値は変えていません。

### TS クロック

256QAM の J.83B の TS は約 38.8Mbps です。  
XIT-SQR100 の地デジの設定 (高い周波数・ハーフレート) は PX-MLT 系の J.83B の設定と同じクロックですが、この基板では BS/CS の設定 (中間の周波数・フルレート) が地デジより高いレートの TS を運べているため、余裕のある BS/CS の設定を J.83B に使いました。  
J.83B だけパケット間の隙間を挿入する設定 (OTSRATECTRLOFF = 0) は、PX-MLT 系と同じく Sony のコードに従います。  
この選択がシリアル入力の IT9303 で問題なく受信できるかは、実機で確認していません。

### ISDB-C を対象外にした理由

チューナーには ISDB-C 用の行 (`SONY_FREIA_DTV_CABLE_6`) もありますが、ISDB-C は TSMF の分離と null パケットの扱いを選局ごとに切り替える必要があり、依頼の範囲が J.83B だったため、XIT-SQR100 では受け付けていません。

### 使い方

Linux 版は、PX-MLT 系と同じ拡張 ioctl (`PTX_J83B_SYSTEM`) で J.83B を選局します。recisdb では `J83B-H001` などのチャンネル指定を使います ([ISDB-C と J.83 Annex B の選局の仕様](isdbc_tuning.md))。  
WinUSB 版は、`BonDriver_XIT-SQR100.ini` の `System` の行を `;System="ISDB-T,ISDB-S,J.83B"` の行へ切り替えると、`BonDriver_PX4-J83B.ChSet.txt` のチューニング空間が加わります。  
DriverHost は PX-MLT 系と同じく、地上波を受信できる XIT-SQR100 の受信機に J.83B を加えるため、`DriverHost_PX4.ini` に J.83B を書く必要はありません。

## 試験

検証環境で次を実行しました。

- `winusb/px4_winusb.sln` を `Release-static` の x64 と x86 でビルドし、どちらもエラーなしで、追加したファイルの警告もありませんでした。
- Linux カーネルモジュールは、WSL (Ubuntu 24.04) の `linux-headers-6.8.0-149-generic` で `make -C <ヘッダー> M=driver W=1 px4_drv.ko` を実行し、ビルドに成功しました (git の履歴のない複製でのビルドのため、`revision.h` は仮の内容で作りました)。警告は既存の `r850.c` の未使用の表だけで、追加・変更したファイルの警告はありませんでした。`modinfo` で `usb:v06B8p106B` の別名が登録されていることを確認しました。検証環境の WSL で動いているカーネル (6.18) のヘッダーではビルドしていません。
- `winusb/tests/j83b_driver_test` (x64・x86) は、既存の PX-MLT 系の ISDB-C・J.83B の試験に加え、CXD6866AER の J.83B と ISDB-T のレジスターの値、J.83B と ISDB-S の切り替えと停止、周波数の範囲外の拒否、J.83B の選局の20か所の I2C の失敗で状態を不明へ戻しゲートを閉じること、XIT-SQR100 の TS クロックの値 (ISDB-T・ISDB-S・ISDB-C・J.83B) を確認し、すべて成功しました。PX-MLT 系の TS クロックの既存の確認も成功し、PX-MLT 系の値は変わっていません。
- `python pcsc/tests/check_card_guids.py` は、XIT-SQR100 を含む 17 組の VID・PID・GUID が INF と一致しました。
- `winusb/pkg/signing-tools/sign.ps1` でカタログを作り直し、`XIT-SQR100.inf` を含むすべての INF の収録と署名を確認しました。
- `winusb/build.ps1` は、ソリューションのビルド、自動試験、配布物の作成 (`BonDriver_XIT-SQR100_32bit`・`_64bit` を含む)、配布物の INF とカタログの検査、全 BonDriver のフォルダーの機器定義の検査までは成功しました。その後の RTL-SDR の配布物の作成の段階で `'vswhere.exe' is not recognized` により停止しており、以降の段階 (MSi2500・PX-S1UD・PIX-DT295 の配布物の検査、アプリケーションの署名の検査) は実行されていません。この段階は今回の変更と関係しない処理ですが、変更前の版で同じ停止が起きるかは確かめていません。

## 未確認の範囲

- 実機でのすべての動作 (このリポジトリの版の USB 認識・初期化・選局・受信・カード・USB の抜き差し・終了処理)

- 移植元で未解決の地デジの受信開始直後の TEI と形式不正、長時間の連続受信
- WinUSB 版の TS の暗号化の無効化の追加が受信へ与える影響
- 基板電源の GPIO (H5・H2・H7) の信号名と極性
