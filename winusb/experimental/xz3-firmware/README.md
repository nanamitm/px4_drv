# GV-MVP/XZ3 FR30 I²C中継ファームウェア

GV-MVP/XZ系のUSBブート経路から、FR30でI²Cの書き込み、読み出し、反復START付き書き込み・読み出しを実行する試作です。給電、ピン設定、チューナー選局、TS転送はホスト側の実装範囲です。I²Cコントローラーの転送手順はPIX-DT295の `direct_pump.c` を参照し、USB入口はXZのブートコードに合わせています。

## ビルドと検証

FR30 GCCとBinutilsを使用します。

```sh
python3 build.py --out /tmp/xz3-i2c
cc -std=c11 -Wall -Wextra -Werror test_relay.c -o /tmp/xz3-relay-test
/tmp/xz3-relay-test
```

出力はUSBフック用の `hook.bin`（RAM `0x000e9a10`）と、本体の `relay.bin`（RAM `0x000ea61c`）です。ロード側では、XZの起動状態と書き換え対象の元バイト列を確認し、作業領域とステージングを退避したうえで、本体、フックの順で適用する必要があります。終了時はフックから先に復元し、読み戻して照合します。通常のUSB読み出しは元の処理へ戻ります。

Windows x64のWinUSBを使用し、GV-MVP/XZ3のRAM上で状態取得と未初期化時の転送拒否を確認しました。試験後にフック、本体領域、ステージングを復元し、退避内容との一致を確認しています。実機ではI²Cバスを駆動する転送まで未検証です。模擬MMIO試験では複数操作、反復START、不正な操作列、NACK、バスエラー、タイムアウト、STOP後のバス固着を確認できます。

## パケット

ステージング `0x000c4600` に64バイトを末尾のワードから書き、マジックを最後に書きます。同じアドレスから64バイト読み出すと処理が実行されます。先頭6ワードはビッグエンディアンです。

| ワード | 要求 | 応答 |
| --- | --- | --- |
| 0 | マジック `0x585a4931` | 同左 |
| 1 | シーケンス番号 | 同左 |
| 2 | 操作番号 | 操作番号の最上位ビットを設定 |
| 3 | 操作データのバイト数 | 結果コード |
| 4 | 0 | 完了したI²C操作数 |
| 5 | 0 | 応答データのバイト数 |

操作1は状態取得で、STATUS、CONTROL、DIVIDERの3ワードを返します。操作2は残り40バイトに `[7ビットアドレス, 書込長, 読出長, 書込データ...]` を並べます。各操作の書込長と読出長は最大8バイトです。全体を検証してから実行し、失敗時は後続の操作を打ち切ります。完了済みの書き込みには副作用があるため、ホストでバッチ全体を再送するときは個々の操作の再実行可否を考慮してください。

結果コードは順に成功、形式不正、タイムアウト、バスエラー、NACK、STOP後のタイムアウト、未初期化です。未初期化の判定には、公開mAgicVISIONファームウェアのXZ初期化データで使用されているDIVIDER値 `0x3c` を使います。この値だけで周辺回路の給電やピン設定を確認できるわけではありません。
