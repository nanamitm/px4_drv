# PIX-DT295 SERVICE内テレメトリー

これはmAgicVISION 0.1.1の特定バイナリーを入力とする**診断用派生イメージ**の生成器です。独立ソースファームウェアの実装とは別物で、通常配布物への組込みはありません。入力SHA256が一致する場合だけ生成できます。

既存ローダーが保存・復元するDT295ブート領域は `0x000E1000..0x000E17FF` の2048 bytesです。元の1552 bytesを保持し、344-byteのFRコードを `0x000E1610` へ追加します。既存のバッファー、residentのBSS、スタック領域を配置先として流用する必要はありません。

変更するresidentコードは3か所の呼出し先即値だけです。共通ディスパッチ、DT295の有限FIFO補充ループ、USB FIFO詰め込みの呼出しを診断ラッパーへ向けます。既定の64成功版はループ先頭44 bytesと元の命令列の完全一致を生成時に検査します。`--success-limit 128` / `256` は送出成功上限だけを変える対照試験用で、4096試行・初期化・選局設定・USB要求数・TS内容は共通です。128版は上限即値、256版は上限即値の命令幅と必要な分岐変位だけを許容し、それ以外の変更を生成器で拒否します。256版も既存の整列パディング内に収まり、全体は344 bytesです。build IDは64版 `DTS1.001`、128版 `DTS1.128`、256版 `DTS1.256` とし、immutable加算チェックサムを再計算します。

## 応答

DT295用テーブルのSERVICE（command 24、16進）だけで、64-byte応答のpayload 24..63へBE32を10語返します。

| 語 | 内容 |
|---|---|
| 0 | DTS1 magic、44545331 |
| 1 / 2 | SERVICE前の生産位置 / 消費位置 |
| 3 / 4 | SERVICE後の生産位置 / 消費位置 |
| 5 / 6 | 補充ループの試行回数 / 成功回数 |
| 7 | FIFO詰め込み関数が1（FIFO not ready）を返した回数 |
| 8 | リング容量 |
| 9 | FIFO詰め込み関数の呼出し回数 |

入力不足など、FIFO関数に到達しない非進行も試行回数には含まれます。エラーによる早期終了は元の戻り値を維持します。他コマンド・他機種テーブルは元処理へ通過します。応答ヘッダー・status・detailは保持されます。

計測用ポインターはコマンド実行中だけ追加ブート領域内の専用1語へ格納し、終了前に0へ戻します。カウンター本体はラッパーが確保した48-byteスタックフレームに置き、元のディスパッチャーが応答を組み立てた後でpayloadへコピーします。呼出し元の保存レジスターと戻り値、FIFO関数へ渡すスタック引数2個を保持します。

## 検証と利用

```powershell
python build.py --input <magicvision-dt295.bin> --out <output-directory> --success-limit 64
python test_model.py <output-directory>
```

生成器はWSL Ubuntu内のFR30 GNU Binutils 2.43.1を使用します。`--tool-root` でビルド済みツールのディレクトリーを指定できます。生成物は入力と同じライセンス条件を確認する必要があり、このディレクトリーへ元ファームウェアや生成バイナリーを追加する必要はありません。

命令モデルの対象は追加したFRコードだけで、割り込み、キャッシュ、CPU実行環境の実機適合を保証するものではありません。バイト一致検査、9ケースの命令モデル、実生成SBC2を使用したx86/x64の模擬USBロード・復元も併用します。

測定用Hostは `DT295_STREAM_TRACE_DIR` 指定時に既存SERVICE応答からCSVを作ります。`DT295_STREAM_TRACE_RING` を外すと追加USB読出しは入りません。冷起動からロードした計測の終了時に `DT295_STREAM_TRACE_RESTORE` を指定すると、そのHostが保持する元のスナップショットを復元する経路になります。既存イメージを採用して開始したHostは元のスナップショットを持たないため、この復元要求を拒否します。

ファームウェア内部の追加命令にも実行時間があるため、追加USB転送なしという性質と無負荷測定は同義ではありません。通常版での結果とSERVICE所要時間・レートを比較する必要があります。

## 実機結果

Rev.01 / TC90532XBGの申告実機でCS・地デジ・BS各30秒の診断応答を取得し、試験前のRAM・ブート領域の復元まで確認しました。条件・欠落・計測負荷・限界は[実機測定](../../docs/pix-dt295-service-telemetry.md)を参照してください。
