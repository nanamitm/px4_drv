# GV-MVP/XZ3 長時間受信（2026-11-12）

TVTest で GV-MVP/XZ3 を約3時間連続して受信し、TS の欠落と DriverHost の TS リングの未処理量を記録した結果です。

この文書の「検証環境」は次の構成を指します。

- Windows 11 Pro x64（10.0.26300）、USB で接続した GV-MVP/XZ3（`04bb:0530`）1台
- BS/110度CS アンテナ（外部から給電、`LNBPower=0`）
- 専用の `GV-MVP-XZ3.inf`（px4_drv CA の署名、Driver Version 1.0.0.0）で導入し、XZ3 の定義は専用の `DeviceInterfaceGUID={44e46df4-5fbd-40c8-84d6-e56ddceb12be}` と `Experimental=true`
- 64ビット版 TVTest と同じフォルダーに、develop `8234d9e` からビルドした x64 版の `BonDriver_XZ3.dll`、`DriverHost_PX4.exe`、`WinSCard.dll` を配置
- `DriverHost_PX4.ini` と `BonDriver_XZ3.ini` は `DebugLog=true`
- XZ3 は内蔵カードリーダーを持たないため、同じ DriverHost に接続した PIX-DT295 の内蔵カードリーダーへ B-CAS カードを挿入

BonDriver は TVTest へ渡す直前で TS の連続性を数えています。XZ3 の DriverHost は受信段で TS の連続性を数えていないため、欠落の判定は BonDriver の値によります。DriverHost は約10秒ごとに TS リングの統計を記録します。

## 結果

110度CS ND06（1,693,000 kHz、TSID `0x7060`）を 13:18:56〜16:16:14（2時間57分）受信しました。

| 項目 | 値 |
|---|---:|
| BonDriver の出力パケット | 368,999,424 |
| 平均の流量 | 約6.5 MB/秒 |
| CC の飛び、同じ CC での内容の変化、重複 | 0 |
| adaptation field だけのパケットの CC の不一致 | 0 |
| 同期、TEI、再同期で捨てたバイト、形式不正 | 0 |
| 出力の最大の空き時間（`max_gap_us`） | 0 |

- BonDriver の約10秒ごとの記録1,023件と、受信終了時の集計のいずれでも、上の異常は0件でした。
- 受信を閉じると DriverHost は起動用の RAM を戻し（`boot RAM restored`）、約13秒後にアイドル終了しました。

## TS リング

XZ3 の TS リングは 6,291,456 バイトで、衛星の流量では約0.94秒で満杯になります。DriverHost は操作12の要求ごとに、ファームウェアが返す未処理量の最大値と要求の時間を記録します。

| 項目 | 値 |
|---|---:|
| 要求の回数 | 22,523（10秒あたり22回） |
| 未処理量の最大値 | 124,032 バイト（リングの約2%、16:02:25） |
| 10秒ごとの未処理量の最大値（ほかの区間） | 多くは約15〜25 KB |
| リングの3/4を超えた要求 | 0 |
| 要求の間の最大の空き時間 | 2,376 µs |
| 1回の要求の時間 | 約472 ms（最大 487,043 µs） |

- 1回の要求で約3 MiB を読み出すため、要求の時間はほぼ一定の約472ミリ秒です。最大の 487 ms は未処理量が最大になった 16:02:25 の区間と同じで、その区間でもリングの約2%にとどまりました。
- 要求の間の空き時間は最大でも約2.4ミリ秒で、リングが満杯になるまでの約0.94秒に対して十分な余裕があります。

## 内蔵カードリーダー

- 受信中は PIX-DT295 の内蔵カードリーダーを `WinSCard.dll` から使いました。PIX-DT295 の受信機は、XZ3 の受信を始める前に約7秒開かれ、その後は使われていません。
- DriverHost はカード操作と APDU の成否を記録しないため、カード通信の回数と失敗数はこの記録に含まれません。TVTest のスクランブル数も記録していません。

## 確認していない条件

- x86 版の実機での長時間受信
- 地デジと BS の長時間受信
- 録画ファイルへの書き出しを含む長時間録画
- USB の抜き差し、無信号の継続、スリープ復帰
- 複数台の同時接続、LNB 給電
- DriverHost の受信段での TS の連続性（計数の対象外）
