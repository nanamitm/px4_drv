# Windows デバイス操作の設定と検証

Windows の DriverHost_PX4 は、USB 転送、内蔵カード、共有電源、複数台の選択を管理します。
この文書の設定は開発版の WinUSB ホストが対象です。Linux カーネル版の設定ではありません。

## USB 転送の停止と RAW_IO

IT930x 系の停止処理は、Abort/Cancel を要求した後に投入済みの全要求の完了を回収し、
その後で OVERLAPPED、イベント、受信バッファを解放します。
ストリームの中止が既存の USB 制御タイムアウト内に完了しない場合は、
未完了要求の領域をプロセス終了まで保持し、そのデバイスでの受信再開を拒否します。
この場合はエラーを記録し、利用終了後にホストを再起動します。
制御送受信と同期ストリーム読み出しも、中止後の完了を待ってから呼び出し元へ戻ります。
中止要求の発行だけではバッファの寿命は終わりません。

RAW_IO を使用する受信は、実際の endpoint の USB パケットサイズと
WinUSB の MAXIMUM_TRANSFER_SIZE に基づいて転送長を検査します。
丸め後に上限を超える設定は受信開始前にエラーとなります。
USB パケットサイズは TS の188バイトとは別の単位です。
RAW_IO の復元に失敗したデバイスは、同じハンドルで受信を再開せず、再オープンを必要とします。

PX-S1UD は制御メッセージと TS の境界を保持するため RAW_IO を使用しません。
PX-BCUD の isochronous 転送や、各追加機種の専用バックエンドの転送方式は維持します。

## 高精度待機の比較測定

通常は従来の16ms単位の余裕を維持します。短い待機を減らす比較測定を行う場合は、
使用する DriverHost_PX4.ini に次を設定します。

```ini
[DriverHost_PX4]
HighPrecisionDeviceWait=true
```

有効時は、共通の `msleep` を高分解能 Waitable Timer で実行します。
同時呼び出しはそれぞれ別のタイマーを使用します。
タイマーを利用できない環境では Sleep へ戻ります。
基板ごとに明示されている Sleep(80) 等の電源シーケンスは変更しません。
設定を省略するか false にすると従来の待機へ戻ります。変更の反映にはホストの再起動が必要です。

通常時と高負荷時の選局時間、再オープン、TS の連続性、受信中のカード操作を比較してから使用します。
自動試験の待機精度確認は、実機での待機時間短縮の妥当性を保証しません。

## カード接続と抜去

接続は、その時点で観測したカードの世代へ結び付けます。
抜去または USB 切断を観測した後は、再挿入されていても古い接続からの STATUS、RESET、
TRANSMIT、BEGIN_TRANSACTION を拒否します。
古い接続で END_TRANSACTION の RESET を要求しても、置き換わったカードはリセットせず排他だけを解除します。
WinSCard 側には SCARD_W_REMOVED_CARD を返します。

利用側は SCardReconnect または切断・新規接続で現在のカードへ接続し直します。
同じカードへの通常の RESET や、物理抜去を伴わない T=1 通信失敗からの回復は、
カードの置き換えとは区別します。
接続を持たない状態監視は再挿入を検出し、ATR を再構築できます。
ホストが観測できない短時間の抜差しまで識別できるという保証はありません。

## PX-MLT の共有電源

チューナーとカードの既存の利用参照を維持し、最後の利用者が閉じたときだけ電源を切ります。
GPIO 操作の失敗は電源 OFF の成功として扱わず、状態を不明として保持します。
部分的な電源投入に失敗した場合も停止を試み、元のエラーを返します。
次の投入では未使用であることを確認して停止状態を再構築します。
利用者が残る状態不明の電源を再投入したり、USB 切断後に GPIO を操作したりしません。

PX-MLT8PE の3チューナー側・5チューナー側は既存の別 USB デバイスとして扱います。
別機種の GPIO や受信機数を流用する変更は含みません。

## 同型機を明示的に選択する

DriverHost の DebugLog を有効にして起動すると、次の形式で各 USB デバイスの識別情報を記録します。

```text
USB device: model=... id=0123456789ABCDEF serial=...
```

BonDriver の INI で、使用する ReceiverDefinition の DeviceName を次のいずれかに設定します。
実際のログにある ID または USB シリアルに置き換えてください。

```ini
[ReceiverDefinition0]
DeviceName="@id:0123456789ABCDEF"
Index=0
```

```ini
[ReceiverDefinition0]
DeviceName="@serial:123456789012345"
Index=0
```

Index、System、DeviceGUID、ReceiverGUID 等は引き続き条件に使います。
既存の同じ節の設定を維持し、DeviceName だけを置き換えます。
通常の製品名や空の DeviceName による従来の空き受信機選択も利用できます。

同じシリアルに異なる USB デバイスが一致した場合は、片方が使用中でも明示選択を失敗させます。
指定した機器がない場合も別の機器へ自動的に切り替えません。
ID は Windows のデバイスインターフェースパスから生成するため、
USB 接続位置やドライバー登録の変更で変わる場合があります。
シリアルは USB インターフェースが返す文字列そのものです。筐体の base serial を推定しません。
同じ USB 内の複数受信機は同じ ID を使い、Index 等で区別します。
この選択機能には対応した DriverHost が必要です。

## 自動試験と実機確認の境界

`winusb/build.ps1` は x86/x64 のビルドに加えて、次を実行します。

- `winusb_lifetime_test`: 実際の bus 実装へ模擬 WinUSB を注入し、停止・開始失敗・制御タイムアウト後の完了回収、転送長の上限・丸め・溢れ、ポリシー復元失敗を確認。
- `device_wait_test`: 従来待機の境界値、高精度待機の最小時間、同時待機を確認。
- `smart_card_state_test`: 既存の T=1 試験に加え、抜去・再挿入・USB 切断での接続無効化と明示再接続を確認。
- `backend_power_test`: 共有参照、GPIO 失敗、停止失敗後の再投入、切断後の操作拒否を模擬操作で確認。
- `device_identity_test`: 実際の ReceiverManager で同型機・重複シリアル・使用中機器・受信機番号・従来選択・不正 IPC 文字列を確認。

実機の受信、負荷時のドロップ、物理抜差し、長時間録画は別途確認が必要です。
実行中の受信ソフトウェアや既存ホストは、ビルドや模擬試験のために停止しません。

設計の比較資料は [Khronos31/px4-userland 13cf1c5](https://github.com/Khronos31/px4-userland/tree/13cf1c5758c0c962ce2f7bb19cddd84580c93f59) の
libusb transport、Windows stream policy/wait、card service、MLT5 power、identity です。
本実装は既存の WinUSB、名前付きパイプ、BonDriver と機種別電源シーケンスに合わせています。
