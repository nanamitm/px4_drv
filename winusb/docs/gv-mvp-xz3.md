# I-O DATA GV-MVP/XZ3 の Windows WinUSB 対応

GV-MVP/XZ3（USB ID `04BB:0530`）の地デジ・BS・110度CSを、Windows標準のWinUSBと
`DriverHost_PX4.exe` で受信できます。選局・TS転送用のファームウェアはDriverHostに内蔵されています。
地デジと衛星で1受信機を共用します。XZ3からのLNB給電は未対応のため、給電が必要なアンテナには外部から給電します。
既定の `LNBPower=0` で使用します。

## インストール

1. 視聴・録画アプリでXZ3を使用している場合は、使用が終わってから作業します。
2. 共通パッケージの証明書を初めて導入する場合は、`Driver` 内の `cert-install.jse` を実行します。
3. 管理者権限のターミナルで、配布フォルダーから次を実行します。

   ```powershell
   pnputil /add-driver ".\Driver\GV-MVP-XZ3.inf" /install
   ```

4. TVTestなどのアプリに合わせて、`BonDriver_XZ3_32bit` または `BonDriver_XZ3_64bit` の内容を配置します。
   既存のpx4_drvと共用する場合は、配布版のDriverHostを使い、既存のINIにGV-MVP/XZ3の機種定義と受信機定義を取り込みます。
   稼働中の共用DriverHostがある場合は、視聴・録画が終わったあとに更新した版を起動します。
5. `BonDriver_XZ3.dll` を選択し、地デジ・BS・CS110をスキャンします。

## Zadigから移行

ZadigのWinUSBが優先されたままの場合は、デバイスマネージャーでハードウェアIDが
`USB\VID_04BB&PID_0530` の機器を選び、「ドライバーの更新」→「コンピューターを参照」→
「コンピューター上の利用可能なドライバーの一覧から選択」→「ディスク使用」で
`GV-MVP-XZ3.inf` を指定します。既存のチャンネル一覧は引き続き利用できます。

専用INFを使う設定では、XZ3の `DeviceInterfaceGUID` は
`{44e46df4-5fbd-40c8-84d6-e56ddceb12be}` です。
Zadigの共通WinUSB GUIDで動作している環境を継続する場合は、XZ3の定義で
`DeviceInterfaceGUID="{dee824ef-729b-4a0e-9c14-b7117d33a817}"` を使います。

## 検証範囲

次の結果は、ZadigでWinUSBを割り当て、共通WinUSB GUIDで列挙した1台のGV-MVP/XZ3で得たものです。

- x64のBonDriverで地デジ・BS・110度CSの選局、無信号チャンネルからの復帰、閉じて開き直した後の受信を確認しました。
  再オープンを含む451,584パケットで同期エラー、TEI、CC不整合は0件でした。
- x86のBonDriverで地デジ・BS・110度CSの受信と再オープン後の受信を確認しました。
  292,864パケットで同期エラー、TEI、CC不整合は0件でした。
- x64版TVTestで地デジ13〜62chのスキャン、受信できるチャンネルの検出、10秒間の録画を確認しました。
- C/Nは選局直後の最初の要求から有効値を返し、無信号では0 dBに戻ることを確認しました。
- 地デジ13・15chを交互に選ぶ `channel_switch_stress` の6周期で、同期エラー、TEI、CC不整合は0件でした。

2026-11-12には、`GV-MVP-XZ3.inf` と専用GUIDで導入した環境で、x64版TVTestを使い110度CS ND06を約2時間57分受信しました。
BonDriverの出力368,999,424パケットで同期エラー、TEI、CC不整合は0件、TSリングの未処理量はリングの約2%以下でした。
結果と未確認の条件は [長時間受信の記録](gv-mvp-xz3-long-run.md) にあります。

地デジとBSの長時間受信、録画ファイルへの書き出しを含む長時間録画、スリープ復帰、
複数台の同時接続、LNB給電は実機確認の対象外です。
地デジの連続受信は、診断用の経路で13chを約15分受信した記録に限られます。

### USB の接続と抜き差し

PCのUSBポートへ直接接続した状態で、x64版TVTestでBSを受信中にUSBを抜き、約10秒後に同じポートへ挿し直したところ、
BonDriverが挿し直した機器へつなぎ直し、チャンネルを変えずに受信が再開しました。TSリングの未処理量は抜き差しの前後とも約2万バイトでした。

USB 2.0ハブ（USB ID `05E3:0610`）を経由して接続した状態では、抜き差しと関係なく受信できませんでした。
TSリング（6 MiB）がほぼ常に満杯になり（`ring high`）、同期の崩れたTSが破棄されて（`discarded ... TS records with invalid sync`）、
BonDriverの出力では多数のPIDでCCが飛びました。1回の取り出しに約140 msかかり、受信の流量に追いつかなかったためです。
ハブの種類による違いは確かめていないため、PCのUSBポートへ直接接続してください。

GV-MVP/XZ3はシリアル番号を持たないため、接続するポートを変えると内蔵カードリーダーの名前の `(ID: ...)` も変わります。
TVTestのCasProcessorなどでカードリーダーを名前で指定している場合は、ポートを変えた後に指定し直してください。
試験の条件と他の機種の結果は [抜去後の受信機のつなぎ直し](receiver-reconnect-after-removal.md) にあります。

上記の受信結果と2026-11-12の長時間受信の記録は、TS転送の1回の送出量が3 MiBの固定だった版のものです。
内蔵カードリーダーに対応した版では、送出量を流量に合わせて384 KiBから3 MiBの間で選びます。
この版では、地デジ・BS・110度CSを30〜90秒ずつ受信した試験と、次節の110度CSの長時間受信を確認しています。

## 受信中のTS異常

同期バイトが壊れたレコードは記録して捨て、次の192バイト境界から配信を続けます。
機器が一時的に要求量を送出できなかった場合は、発行済みのUSB読み出しに後続のデータを継ぎ足し、読み出しが満杯になってから配信します。USB転送や応答形式の異常は受信エラーになります。
オフライン試験では同期バイトの破損と部分送出の処理を確認しています。実機で受信中に信号を中断し、復帰させる試験は未実施です。

## 内蔵カードリーダー

XZ3本体のB-CASカードスロットを、`WinSCard.dll` から内蔵カードリーダー
`I-O DATA GV-MVP/XZ3 Smart Card Reader` として使えます（実験的）。
受信の有無に関係なく使え、受信中はTS転送の合間にカードと通信します。

ATRが指定するB-CASの19200bpsとA-CASの38400bpsを受け付けます。
A-CASは実機のATR取得と38400bpsでのT=1 IFS応答に加え、修正版のx64ホストと
WinSCardによるT=1接続・切断を3回確認しました（失敗0、接続の最大時間1.081秒）。
利用者からdantto4kでの動作に問題がないとの報告があります。
x86版の実機通信と、受信を伴う長時間のA-CAS通信は未確認です。

T=1応答は、ATRが指定するLRCまたはCRCを含めて全体が揃った時点で上位へ渡します。
CRCの末尾が別々のFIFO読み出しに分かれる場合と、リセット後にLRCのカードへ切り替わる場合を模擬I/Oで確認しています。CRCを指定する実カードでの確認は未実施です。

x64版で、受信していない状態と、地デジ・BS・110度CSを受信しながら `card_reader_reliability` で
カードへのコマンドを200 msおきに送り続けた試験で、カードの失敗とTSの異常（同期エラー、TEI、CC不整合）は0件でした。
受信中の1回のコマンドの時間は最大で約0.5〜0.9秒です。

x64版のlibaribb25で、地デジ13chとBS15/TS0を60秒ずつ受信しながら復号できました。
110度CSは、XZ3のカード通信が遅いため、受信の開始やスクランブル鍵の更新でカードへの要求が続くと、
TSが欠落する可能性があります。110度CS ND06の受信開始から約10秒の間に、TSの欠落を確認しています。
110度CSを録画する場合は、外付けのカードリーダーの使用を検討してください。

2026-11-13には、x64版TVTestでXZ3の内蔵カードリーダーを使い、110度CS ND06を約3時間25分受信しました。
視聴したサービスの復号に問題はなく、受信開始の直後を含めてTSの欠落はありませんでした。
BonDriverの出力427,621,376パケットで、同期エラーとTEIは0件、CC不整合は番組の切り替わりの時刻に1件で、
受信側の記録に欠落がないことから放送側の要因と判断しました。TSリングの未処理量はリングの約16%以下、カード通信の失敗は0件でした。
結果は [長時間受信の記録](gv-mvp-xz3-long-run.md) にあります。
この1回の試験では受信開始時のTSの欠落が再現しなかっただけのため、上記の110度CSの注意は変わりません。

地デジ・BSでの長時間の同時使用、録画ファイルへの書き出しを含む長時間録画、USB接続直後に受信を始める前のカードの使用、x86版のカードは確認していません。
詳細はリポジトリの `winusb/experimental/xz3-firmware/README.md` の「内蔵カードリーダーの調査」と「操作12の送出量」にあります。

実機試験の詳細はリポジトリの `winusb/experimental/xz3-firmware/README.md` に記録されています。
