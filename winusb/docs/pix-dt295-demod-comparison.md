# PIX-DT295 復調器・RF初期化の静的比較

## 結論

mAgicVISION旧版の初期化テーブルは、pix-userlandが公式ファームウェア由来のmaterialから使用する4表・94組と全一致しました。新版は93組が一致し、地デジ側の `0x70` だけが異なります。さらに新版は初期化末尾に3書き込みを追加しています。

これだけではmAgicVISIONがTC90522XBG専用であるとは判断できません。両ICのレジスターマップや実機IDによる同定を行っていないため、TC90532XBGとの完全互換性も保証できません。共通の初期化を使い、一部の設定と転送方式が異なる、という説明が静的比較に合っています。

## 比較対象

- mAgicVISION 0.1.0: container SHA256 `d9f549b29d286c2ff1e7daf4237e2205bb8a5a2affbb98362bce137b8b42a33f`
- mAgicVISION 0.1.1: container SHA256 `0b2147e190afc7626165594fdedbedc6461c0e1f044b17742123b77fc5026fcc`
- pix-userlandのDT295 material: D295A1、SHA256 `3cabe15f585a8a7a7d7b9b3db548b677b0732c13926dc3a2b5270acf1bc6ffc8`
- 呼出し列の比較: DT295-TVTest-Kit 1.1同梱ソースの `dt295.c`。既存の受信比較は[ファームウェア比較](pix-dt295-fw-comparison.md)を参照。

公式由来テーブルを使うpix-userland経路との比較であり、純正WindowsドライバーのUSB通信を採取した比較ではありません。

## テーブルの一致

| 対象 | 組数 | 旧版 | 新版 |
|---|---:|---|---|
| 地デジ復調器 | 22 | 全一致 | 21組一致、70のみ変更 |
| 衛星復調器 | 18 | 全一致 | 全一致 |
| 地デジRF・表1 | 26 | 全一致 | 全一致 |
| 地デジRF・表2 | 28 | 全一致 | 全一致 |

テーブルのmaterial内アドレスは順に `0x841D0`、`0x845A0`、`0x84630`、`0x84700`。mAgicVISION側は同じレジスター・値をコマンド列に直列化しています。

## 旧版から新版への差分

| 地デジ側レジスター | 旧版／公式由来表 | 新版 | 差分 |
|---|---|---|---|
| 70 | 38 | 18 | bit 20をクリア |
| 47 | 該当する末尾書き込みなし | 00 | 初期化末尾へ追加 |
| 4F | 該当する末尾書き込みなし | 05 | 初期化末尾へ追加 |
| 72 | 該当する末尾書き込みなし | 00 | 初期化末尾へ追加 |

値・アドレスは16進数です。「書き込みなし」はレジスター値が0という意味ではありません。各ビットの仕様・意図は未確認で、TSクロック設定やICリビジョン対応と断定しません。

旧版の初期化スクリプトは `0x803ACB8C` から992 bytes・134レコード、新版は `0x803ADBF0` から1010 bytes・137レコードです。全レコードを比較すると差分は上記4点に限定されます。スクリプト内の待機指定は両方とも合計130 msですが、呼出し側や転送にかかる時間は含みません。

## pix-userlandの呼出し列との比較

ソースの `table_write`、`frequency`、`tuner_initialize`、`sat_rf_sleep`、`sat_initialize` を抽出し、I/O関数をログ出力に置換した機器非接続のdry-runを実行しました。これは実機I²Cトレースではありません。

I/Oコマンドの順序とペイロードを比較すると、pix-userlandの137コマンドに対し、旧版の134コマンドは地デジ初期化末尾の `25=00 / 23=4D / 03=90` がない点だけが異なります。新版は同じ3コマンドを省き、70の変更と47・4F・72の追加があります。橋渡しICの電源・リセット操作や呼出し側の待機まで同一とする結果ではありません。

## 選局・TS出力制御の対応

新版のFR命令列では、次の主要な操作がpix-userlandと対応しています。

| 操作 | 対応する設定 |
|---|---|
| 地デジ出力停止 | 1D / 1E / 1F = AA |
| 地デジ出力再開 | 1D=02 / 1E=2A / 1F=8A |
| 衛星出力停止 | 1C=AA / 1F=2A |
| 衛星出力再開 | 1C=08 / 1F=08 |
| 衛星TSID指定 | 8F=上位 / 90=下位 |
| 衛星選局中の地デジ側設定 | 0E=77 / 0F=77 |
| 衛星モードのread-modify-write | A5は40をOR、A3は88でAND後11をOR |

地デジの周波数換算も、入力単位の違いを除けば同じ式です。全分岐・全タイミング・実機読戻しの一致までは検証していません。

## 次の切り分け

旧版でもCSの欠落が発生していたため、新版で増えた4設定だけでは過去の症状全体を説明できません。既に計測したSERVICE／USB転送の待ち時間と並行して、これら4設定の影響を分離する必要があります。

まず設定の読戻し可否と安全なアクセス経路を確認し、旧版／新版の同一条件比較を行います。値を変更する場合は70と末尾3設定を分けた対照試験にし、全多重TSの入力レートとCCを測定します。キットはPID選別経路なので、保存TSのレートだけをmAgicVISIONと直接比較しません。

今回、機器への書き込み・ファームウェアの改変・デプロイは行っていません。リビジョン別HALを実装する根拠も、現時点では不足しています。
