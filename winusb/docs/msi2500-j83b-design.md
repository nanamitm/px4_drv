# RSP1 互換機 (MSi2500/MSi001) による J.83 Annex B 受信の設計

Mirics MSi2500 と MSi001 を搭載した SDRplay RSP1 互換機で、スカパー！プレミアムサービス光の
ITU-T J.83 Annex B (256QAM、5.6 Msps) を復調し、BonDriver から TS として受信するための設計資料。
地上デジタル放送のフルセグ受信 ([msi2500-fullseg-design.md](msi2500-fullseg-design.md)) の helper と
DriverHost への組み込みを土台にする。

2.1〜2.4 節の測定値は、試作ツールによる取り込みとオフライン復調の結果である。2.5 節は helper の Rust 実装
(J1、オフライン) で同じ取り込みを復調した結果、2.6 節は helper の実時間の受信 (J2)、2.7 節は DriverHost と
BonDriver を経由した受信 (J3) の結果である。

ほかの地域・時期の搬送波配置、純正の SDRplay RSP1、32 ビット版での実時間の受信は未確認。

## 1. 位置づけ

このフォークは、PX-MLT 系 (CXD2856ER / CXD2858ER) で J.83B を実験的に受信する経路を持つ
([isdbc_winusb_experimental.md](../../docs/isdbc_winusb_experimental.md) の「J.83B 5.6 Msps の実験機能」)。
BonDriver の系統 `J.83B`、チャンネル定義 `BonDriver_PX4-J83B.ChSet.txt`、DriverHost の `SystemType::J83B` と
選局経路 `ReceiverBase::TuneIsdbC` はすでにある。この設計は、そこへ MSi2500 の helper による
ソフトウェア復調を受信機の 1 つとして加える。

## 2. 検証環境で確認した事実

### 2.1 搬送波の配置と入力レベル

チャンネル定義の H001〜H105 (中心 93.25 MHz から 6.5 MHz 間隔) を、帯域幅 7 MHz、各 0.5 秒で取り込んだ。
帯域内 (±0.2〜2.6 MHz) と帯域端 (3.4〜3.9 MHz) の電力比が 23 dB 以上だった周波数は次のとおり。

| 範囲 | 搬送波 | MSi001 の帯域 |
|---|---|---|
| 112〜139 MHz | H004、H005、H007、H008 | バンド III (LO 分周 16) |
| 561〜587 MHz | H073、H075、H076、H077 | B4/5 (LO 分周 4) |

利得 (`--gain`、MSi001 の合計 dB) は、46 で信号の成分が −27 dBFS 前後と小さく、60 で H007 と H008 の ADC が飽和した。
52〜58 で信号の成分が約 −16 dBFS になり、MER が最も高かった。地上デジタル放送のアンテナ入力で使った 40 より大きい値が要る。

### 2.2 信号の形式

H008 (138.75 MHz) の取り込みで、|x|² のスペクトルにシンボルレートの周期定常の線 (8.127 MS/s では
8.127 − 5.6 ≈ 2.53 MHz に折り返す) が雑音より 35 dB 高く現れ、単一キャリアの QAM であることを確認した。
推定したシンボルレートは 5.599986 Msym/s で、公称 5.6 Msym/s との差 −2.5 ppm は受信機の時計のずれとみられる。
等化後の I 成分の振幅分布に 16 個の山があり、256QAM である。

### 2.3 MER

試作の復調 (windowed-sinc 補間で 2 サンプル/シンボル、ルートロールオフ α=0.12、T/2 間隔 32 タップの等化器を
CMA で収束させた後に判定帰還 LMS と 2 次 PLL へ切り替え) で求めた MER は次のとおり。

| 搬送波 | 利得 | MER |
|---|---|---|
| H008 (138.75 MHz) | 52 | 28.3 dB (収束後 7.5 万シンボル) |
| H008 | 58 | 28.6 dB (同)、30.0 dB (収束後 27 万シンボル) |
| H007 (132.25 MHz) | 52 | 27.7 dB (同 7.5 万)、28.7 dB (同 27 万) |
| H075 (574.25 MHz) | 55 | 19.8 dB (PLL 既定) → 26.1 dB (PLL 帯域 10 倍)、27.2 dB (同、収束後 27 万) |

- CMA から判定帰還へ切り替える時点の位相と周波数のずれを 4 乗法で推定して PLL の初期値にしないと、
  256QAM の格子で位相を取り違え、MER が約 19.8 dB で止まることがあった。
- バンド III では、利得 52 と 58、PLL の帯域 1 倍と 3 倍、IQ の不平衡の補正 (共役の枝) の有無で MER がほとんど変わらなかった。
- UHF では PLL の帯域を広げるほど MER が上がり、位相雑音が律速とみられる。MSi001 の UHF では LO の分周比が
  バンド III の 1/4 になり、シンセサイザーの位相雑音がその分大きくなることと整合する。

### 2.4 誤り訂正 (ITU-T J.83 (12/2007) Annex B に基づく試作)

等化後のシンボルを Annex B の誤り訂正の連鎖にかけ、次のことを確認した。

- **トレリス符号化変調 (B.5.5)**: 配置表 (図 B.19) では、符号化するビット C4 が I の番号の偶奇、C0 が Q の番号の偶奇に当たる。
  2 本の BCC (G1 = 1 + D² + D⁴、G2 = 1 + D + D² + D³ + D⁴、パンクチャ [0001;1111]) をそれぞれビタビで復号し、
  トレリス群 (5 シンボル) の境界は再符号化の不一致で決まった (正しい境界 0.4%、ほかの 4 通り約 5%)。
- **配置の向き**: 検証環境の取り込みでは、配置を共役にした (Q の符号を反転した) 場合だけ、変換なしで
  フレーム同期と RS 符号語が揃った。ゼロ IF の I/Q の向きによるスペクトルの反転とみられる。
  90° 単位の回転は、差動プリコーダー (図 B.16) の逆演算で吸収される。
- **フレーム同期 (B.5.3)**: 差動の逆演算の出力を群ごとに W0 Z0 W1 Z1 W2 Z2 W3 Z3 の順に並べると、
  同期パターン `71 E8 4D D4` が 2,076 群ごとに現れ、50 フレームで取りこぼしはなかった。
  制御語は `0101` で、インターリーブは I = 32、J = 4 だった。
- **ランダム化 (B.5.4)**: f(x) = x³ + x + α³ の LFSR を全 1 で初期化する。仕様の図からは出力の取り出し位置が一意に読めず、
  6 通りを試した。RS 符号語が揃ったのは、Galois 形 (s0 ← α³·s2、s1 ← s0 + s2、s2 ← s1) で s2 を出力する場合だけだった。
- **RS (B.5.1)**: GF(128) (p(x) = x⁷ + x³ + 1) の拡張 RS(128,122)。根 α¹〜α⁵ と、α⁶ での値を末尾の拡張シンボルに持つ。
- **MPEG パケット (B.4)**: RS のメッセージシンボルを 7 ビット、MSB 先頭で並べたビット列の中で、
  パケットの境界は PID の偏りから求めた。チェックサムのバイトを `0x47` に戻すと TS として整合した。

| 搬送波 | MER | 符号化ビットの誤り率 | RS (訂正なし / 訂正 / 訂正不能) | TS |
|---|---|---|---|---|
| H008 | 30.0 dB | 8.1×10⁻⁴ | 4,258 / 23 / 0 | 2,430 パケット、TEI 0、CC 0、TSID 0x3014 |
| H007 | 28.7 dB | 3.1×10⁻³ | 4,276 / 5 / 0 | 2,430 パケット、TEI 0、CC 0、TSID 0x3027 |
| H075 | 27.2 dB | 1.7×10⁻² | 911 / 1,341 / 1,325 | 復号できず |

訂正した RS ブロックは、H008 と H007 ではいずれも 1 シンボルの誤りだった。
各搬送波とも試験したのは約 0.09 秒 (49 フレーム) で、長時間の安定性は未確認。
MER 28.7 dB と 27.2 dB で結果が分かれ、256QAM の J.83B はおよそ 28 dB を境に復号できなくなる。

MPEG のチェックサム (B.4) は、パリティ検査行列を f(x) = [1 + x¹⁴⁹⁷ b(x)] / g(x) の 1,497 個の係数を逆順に並べたものとし、
症候の S0 を最上位ビットにした場合に、取り込んだ 4,858 パケットのすべてで `0x47` になった。
チェックサムのバイトは各パケットの先頭 (同期バイトの位置) にあり、直前のパケットの 187 バイトに対する値である。

### 2.5 Rust 実装 (J1) による復調

helper の `qam.rs` と `j83b.rs` で、2.3 節と同じ取り込みを先頭から通して復調した結果は次のとおり。
信号の長さは各 1.8〜2.3 秒 (957〜1,229 フレーム) で、いずれも捕捉は 1 回、フレーム同期の喪失は 0 だった。

| 取り込み | MER | RS (訂正なし / 訂正 / 訂正不能) | チェックサムの不一致 | TSID |
|---|---|---|---|---|
| H008、利得 58 | 30.9 dB | 83,753 / 432 / 0 | 0 | 0x3014 |
| H008、利得 52 | 31.1 dB | 108,121 / 0 / 0 | 0 | 0x3014 |
| H008、利得 46 | 30.8 dB | 84,185 / 0 / 0 | 0 | 0x3014 |
| H007、利得 52 | 29.3 dB | 84,153 / 32 / 0 | 0 | 0x3027 |
| H075、利得 55 | 28.2 dB | 103,751 / 3,805 / 31 | 26 | 0x4028 |

- 試作より MER が 0.6〜1 dB 高い。補間を RRC の整合フィルターと一体の多相フィルターにし、タイミングを Gardner 型で
  追従したことによるとみられる。タイミングのずれは +2.1〜+3.0 ppm、搬送波の残差は約 −380 Hz (UHF の H075 は約 −1.5 kHz) だった。
- H075 は試作では復号できなかったが、訂正不能が 107,587 ブロック中 31 まで減った。PLL の帯域を 2〜10 倍にしても
  MER は 28.2 dB のままで、訂正不能は 44〜59 と減らなかったため、残りの誤りは PLL の帯域では解消しない。
- 処理時間は、検証環境の CPU の 1 コアで、1 秒分の信号に対して復調約 0.5 秒、誤り訂正約 0.43 秒だった (x64)。
  32 ビット版では復調約 0.68 秒、誤り訂正約 0.69 秒だった。復調と誤り訂正は別スレッドで動かす (3 節)。

### 2.6 実時間の受信 (J2)

`live --system j83b` で検証環境の機器から受信した結果は次のとおり。いずれも利得 46、受信中の欠落による
状態の作り直しを除いて捕捉は 1 回だった。CPU は helper のプロセス全体の平均である。

| 搬送波 | 時間 | USB の欠落 | MER | RS (訂正 / 訂正不能) | チェックサムの不一致 / TEI / CC | CPU (平均 / 最大) |
|---|---|---|---|---|---|---|
| H008 | 600 秒 | 10 回 (520,120 サンプル) | 30.1〜30.6 dB | 80 / 0 | 0 / 0 / 0 | 1.00 / 1.25 コア |
| H007 | 600 秒 | 9 回 (1,583,292 サンプル) | 29.0〜29.6 dB | 1,917 / 0 | 16 / 22 / 10 | 1.00 / 1.13 コア |
| H007 (再試験) | 600 秒 | 0 回 | 28.8〜29.2 dB | 3,855 / 0 | 0 / 0 / 0 | 1.00 / 1.13 コア |

- 利得 58 では H007 と H008 で ADC の最大値に達するサンプルが 1×10⁻⁴〜5×10⁻⁴ の割合で現れ、MER はほとんど下がらないまま
  RS の訂正が全ブロックの 26% へ増えた (5 秒で訂正不能 105)。利得 46 と 52 ではこのサンプルがなく、訂正はほぼ 0 だった。
  2.1 節で最適とした 52〜58 より低い値が要り、適した利得は入力レベルの時間変化で変わる。飽和したサンプルの割合を統計の `clip` に出す。
- H004 と H005 は、シンボルレートは 5.6 Msym/s だが 256QAM の判定での MER が約 23 dB で、フレーム同期を捕捉できなかった。
- USB の欠落はフルセグの設計資料の 11.2 節と同じ等時転送の遅れで、欠落の前後は復調と誤り訂正を作り直す。
  作り直した後は、RS の誤りや TEI を出さずに TS を出し直した。欠落の前後で TS は連続しない。
- H007 の 1 回目の 313 秒の時点で、RS の訂正不能も USB の欠落もないまま、チェックサムの不一致 16 とパケット同期の喪失 2 が起きた。
  RS ブロックが正しいまま TS のバイト列がずれた形で、同期語が一致したフレームで制御語だけが誤ると
  インターリーブの解除を 2 回作り直すという当時の処理と整合する。原因は確定できていないが、制御語の変更は
  2 フレーム続けて同じ値を受けたときだけ反映するように改め、反映を保留した回数を統計の `ctrl_rej` に出す。
  再試験では保留も TS の誤りもなかった。
- 処理系の開始から最初の TS までは 0.26 秒だった。うち約 0.19 秒は、USB の開始区間 (4,096 ブロック) を捨てる時間である。

### 2.7 BonDriver 経由の受信 (J3)

`tests/msi2500_bondriver_live.ps1 -J83B -Channel 7 -AlternateChannel 6 -Cycles 4 -Seconds 30 -IsolatedHost` (x64) で、
同じ接続の中で H008 と H007 を交互に 4 回選局した。各回の TS は 30 秒で、同期の誤り、TEI、CC の途切れ、PAT の誤り、
3 秒を超える空白はいずれも 0、PAT の TSID で前の搬送波の混入がないことも確かめた。品質は各回 100 だった。

- 選局 (`SetChannel`) から戻るまでの時間は、2 回目以降が 421〜438 ms (前の helper の停止を含む) で、
  `ReceiverBase::TuneIsdbC` のロックまでの上限 1 秒に収まった。新しい実行ファイルを初めて起動した 1 回目は 1,422 ms で、
  上限は helper の起動 (`SetFrequency`) から戻った後のロックまでに掛かるため、選局は成功した。
- 最初の TS の時点で信号レベルが 0 になり、試験の取得側が旧チャンネルの TS と判定する問題があった。
  helper の誤り訂正の統計を 16 回に 1 回だけ反映していたためで、TS を出す前に反映するように改めた。
- 同じ構成の ISDB-T (UHF の空間、非同期の選局) も、2 回の各 20 秒で誤りがなかった。

## 3. 構成

```
MSi2500 ─ 取り込み ─ [生ブロックのキュー] ─ QAM 復調 ─ [シンボルのキュー] ─ J.83B 誤り訂正 ─ TS
                                                (タイミング、等化、PLL)      (TCM、同期、逆ランダム化、
                                                                             インターリーブ解除、RS、パケット同期)
```

地上デジタル放送と同じく、取り込み、復調、誤り訂正を別スレッドで処理し、取り込みのスレッドは待たない。
生ブロックの欠落を検出したら、復調と誤り訂正の状態をすべて作り直す。J.83B は階層を持たないため、再多重化はない。

helper の起動形式は `serve --system j83b --frequency HZ` とし、標準出力の形式 (hostproto) は地上デジタル放送と共通にする。

## 4. QAM 復調 (`qam.rs`)

| 処理 | 方式 | 根拠 |
|---|---|---|
| 直流の除去 | 指数平均の減算 | ゼロ IF の直流のずれ (検証環境で約 −30 dBFS) |
| タイミング | Gardner 型の誤差検出で、8.127 MS/s から 2 サンプル/シンボルの時刻を追従する | シンボルレートと受信機の時計の差の追従 |
| 整合フィルターと補間 | ルートロールオフ α = 0.12 を 24 タップ、256 位相の多相フィルターにし、補間を兼ねる | Annex B 表 B.3。表 (約 25 KB) を L1 キャッシュに収める |
| 等化 | T/2 間隔の等化器。CMA で収束させ、判定帰還 LMS へ切り替え | 2.3 節 |
| 搬送波 | 切り替え時に 4 乗法で位相と周波数を推定し、判定帰還の 2 次 PLL へ引き継ぐ | 2.3 節。PLL の帯域は設定で変えられるようにする |
| 配置の向き | 共役を既定とし、同期が取れなければ反転して試す | 2.4 節 |

等化器は T/2 間隔の 32 タップ (16 シンボル分) とした。録画では 16 タップでも MER の低下は 0.1〜0.15 dB だったが、
処理時間の差も 1 割未満だったため、マルチパスへの余裕を残した。

処理時間は演算量より、1 シンボルごとの帰還の連鎖 (補間 → タイミング、出力 → 判定 → 係数の更新、回転 → 判定 → 位相) の
遅延で決まっていた。Gardner の誤差、LMS の更新 (遅延 LMS)、PLL の位相誤差をそれぞれ 1 シンボル遅らせて反映し、
連続したシンボルの計算を重ねられるようにした。いずれのループの帯域も 1 シンボルあたり 1e-2 より十分小さく、
録画の MER は変わらなかった。積和の内側のループは、自動ベクトル化が遅い命令列になったため SSE2 で書いた。

## 5. 誤り訂正 (`j83b.rs`)

2.4 節で確認した解釈をそのまま移植する。

- 2 本の BCC のビタビ: 1 本あたり約 4.5 M ステップ/秒。ISDB-T の B 階層より軽く、ブロック並列の仕組みは必要に応じて流用する
- 差動の逆演算と、90° 回転の候補からのフレーム同期の確定 (探索、確定、喪失の状態遷移)
- 符号化しないビット: 復号した符号化ビットで偶奇を決めた最も近いレベルから、図 B.19 の表で C7〜C0 を得る
- 逆ランダム化、制御語に従うインターリーブの解除 (I・J の組は Annex B 表 B.2)、拡張 RS(128,122) の訂正 (t = 3)
- MPEG パケットの同期: B.4 のチェックサムで境界を確定する。試作の PID の偏りによる方法は、境界を見つけた後の検証にだけ使う
- RS で訂正できなかったブロックを含むパケットは TEI を立てる。DriverHost へ渡す前に hostproto の検査で取り除かれる

## 6. DriverHost と BonDriver

- `msi2500::Device` の受信機は、DriverHost_PX4.ini の `System` に `J.83B` を書いた場合だけ J.83B を受け付け
  (`ISDB-T` は必須)、`params_.system` に応じて helper へ `--system j83b` を渡す。J.83B の周波数はチャンネル定義の
  中心周波数 (kHz) をそのまま使い、地域によるずれを含めて 90〜775 MHz を受け付ける。
- 利得は系統ごとに設定する (`GainDb` と `GainDbJ83B`)。`GainDbJ83B` の既定値は、2.6 節で飽和がなく誤りもなかった 46 とした。
- J.83B の選局は `ReceiverBase::TuneIsdbC` を通り、ロックまでを 1 秒で打ち切る。2.7 節のとおり、2 回目以降の選局は
  helper の停止と起動を含めて約 0.44 秒で収まったため、MSi2500 の受信機の待ち方は変えなかった。`AsyncTune` は
  ISDB-T の選局 (`CheckTuneComplete`) だけに効く。
- TS のリングバッファは、J.83B の TS (約 4.85 MB/s) でも約 3 秒分になる 188 × 81,920 バイトを、系統によらず確保する。
- `BonDriver_MSI2500.ini` に `J.83B` のチューニング空間を加え、チャンネル定義は PX-MLT 系と共通の
  `BonDriver_PX4-J83B.ChSet.txt` を配布物へ同梱する。チューニング空間は UHF が 0、J.83B が 1 になる。
- 試験用の BonDriver クライアント (`rtlsdr_bondriver_live`) は、環境変数で選局する空間と基準のチャンネル、
  ワンセグの PMT の確認の有無を切り替えられる。`msi2500_bondriver_live.ps1 -J83B` がこれを設定する。

## 7. 段階的な実装

| 段階 | 内容 | 完了条件 |
|---|---|---|
| J1 | QAM 復調と誤り訂正の Rust 実装 (オフライン) | 送信側の符号化を試験用に実装した往復試験 (雑音あり) で誤り 0。録画 IQ (H007、H008) で RS 訂正不能 0、TSID が試作と一致 |
| J2 | 実時間の受信 (`live --system j83b`) | H004、H005、H007、H008 で各 600 秒の RS 訂正不能、CC、CPU、欠落の記録。選局からロックまでの時間 |
| J3 | DriverHost と BonDriver への組み込み | BonDriver 経由の選局の切り替えで TSID の混入がないこと、Close/Open の反復 |
| J4 | 文書と配布物 | 導入手順、README、配布物の検査 |

## 8. 未決定事項と制約

- UHF の搬送波 (検証環境では H073、H075〜H077) は、2.3 節と 2.4 節のとおり試作では復号できなかった。
  Rust 実装では H075 の訂正不能が 0.03% まで減ったが (2.5 節)、誤りなしにはならず、原因は PLL の帯域ではない。
  H075 以外の UHF の搬送波と長時間の結果は J2 で記録し、受信できる帯域として扱うかはその結果で決める。
- 64QAM (42 ビットの同期トレーラー、60 RS ブロックのフレーム) と、米国の 5.06 / 5.36 Msps は対象外。
- スペクトルの反転の向きとランダム化の出力位置は、検証環境の 1 台と 1 つの信号で確認した結果である。
- USB の等時転送の遅れによる欠落 (フルセグの設計資料の 11.2 節、11.3 節) は、J.83B でも同じく残る。
